| 항목 | 내용 |
|---|---|
| 모델명 | Yeoyuro Seoul Congestion Estimator |
| 버전 | v1.0 |
| 작성일 | 2026-09-04 |
| **운영 채택 모델** | **L2 Baseline (역 × 방향 × 요일유형 × 시간대 평균)** |
| 보조 모델 | LightGBM Model-2 (역 식별자 제외) — 미관측 역 보간 전용 |

---

## 1. 목적

서울교통공사 1~8호선의 `(역, 방향, 요일유형, 30분 시간대)` 조합에 대해 **과거 패턴 기반 기대 혼잡도**를 추정한다. 이 값은 경로 추천의 체감시간 환산에 입력된다.

```
perceived_time = travel_time × (1 + 0.5 × max(0, 기대혼잡도 − 80) / 100)
```

---

## 2. 사용 금지 해석 (Prohibited Interpretations)

**이 섹션이 이 문서에서 가장 중요하다.** 아래는 데이터가 뒷받침하지 않는 해석이며, 어떤 상황에서도 이렇게 표현하지 않는다.

| 금지 표현 | 사유 | 대체 표현 |
|---|---|---|
| 실시간 혼잡도 예측 | 실시간 위치·재차 데이터 없음 | 과거 패턴 기반 기대 혼잡도 |
| 객차별 혼잡도 예측 | 객차 단위 재차 데이터 없음 | 환승 동선상 유리한 호차/문 |
| 착석 확률 | 좌석 점유 데이터 없음 | 착석 가능성 proxy 점수 |
| 특정 날짜의 실제 혼잡도 예측 | 타깃이 분기·요일유형별 **평균 패턴** | 기대 혼잡 위험도 |
| 무정차 통과 확률 | 관련 데이터 없음 | — |
| "혼잡도를 정확히 예측했다" | baseline 대비 우위 미검증 | baseline 대비 Skill Score 명시 |

## 3. 데이터 범위

| 항목 | 내용 |
|---|---|
| 타깃 원본 | 서울교통공사 지하철혼잡도정보 **11개 스냅샷** (2022-12-31 ~ 2026-06-30) |
| 피처 원본 | 역별 시간대별 이용인원 **48개월** (2022-07 ~ 2026-06), raw 797,946행 |
| 공간 범위 | 1~8호선 서울교통공사 관할 **276개 역** + 분기 계통 6종 |
| 시간 해상도 | 30분 bin, 05:30~25:00 (39 bin) |
| 학습 마트 | **706,678행** / 34 컬럼 |

### 타깃의 성질 (핵심 제약)

혼잡도 원본은 **특정 날짜의 실측값이 아니라 분기·요일유형별 평균 패턴**이다. 격자 `(역 × 방향 × 요일유형 × 시간대)` 하나당 관측치가 **최대 11개**뿐이다.

이 성질이 아래 모든 설계 판단의 근거가 된다.

- random split 금지 (사실상 정답 암기)
- groupby 평균 baseline 이 매우 강함
- 딥러닝(LSTM/GNN) 부적합

## 4. 피처

| 그룹 | 피처 |
|---|---|
| 시간 | `time_bin_index`, `bin_start_min`, `is_am_peak`, `is_pm_peak`, `month`, `quarter` |
| 노선·방향 | `line_id`, `direction`, `day_type` |
| 역 속성 | `is_transfer_station`, `is_branch_row`, `branch_code`, `attribution_flag`, `has_ridership` |
| 승하차 흐름 | `boarding_cnt`, `alighting_cnt`, `flow_total`, `station_flow_total`, `log_flow_total`, `log_station_flow`, `boarding_ratio`, `net_alighting_ratio`, `line_share_in_station` |
| 식별자 | `station_code` — **Model-1 에만 포함, Model-2 에는 제외** |

### 누수 방지 설계

1. **승하차 피처는 스냅샷 직전 90일만 집계한다.** 같은 기간 승하차를 그대로 붙이면 타깃을 다른 형태로 넣는 셈이 된다. 직전 3개월은 실서비스에서도 알 수 있는 정보라 운영 가능하다.
2. **split 은 스냅샷 단위 시간축 고정.**

| split | 스냅샷 | 행 (holdout 제외) |
|---|---|---|
| train | 2022-12 ~ 2025-03 (6개) | 305,274 |
| valid | 2025-06 ~ 2025-11 (3개) | 156,546 |
| test | 2026-03, 2026-06 (2개) | 104,364 |

3. **station holdout**: 282개 역 중 **56개(20%)** 를 학습에서 완전히 제외. 미관측 역 성능을 별도 평가한다.

### 승하차 귀속 예외 (해석 주의)

| station_uid | 현상 | 처리 |
|---|---|---|
| 6_2649 신내 | 승하차 전 기간 0 | `has_ridership=0`, 역 총량으로 대체 |
| 6_2615 연신내 | 6호선 귀속 0 (3호선에 전량) | 동일 |
| 3_321 충무로 | 3호선 총합 136명 | 동일 |
| 2_260 까치산 | 2호선 승하차 없음 (5호선에 전량) | 동일 |

이 때문에 **호선 귀속량과 역 전체 총량을 둘 다 피처로 넣고 모델이 고르게 했다.** 실제로 `log_station_flow`(역 총량)가 `log_flow_total`(호선 귀속)보다 타깃 상관이 높다(0.488 vs 0.448).

## 5. 타깃과 라벨

| 이름 | 정의 | 비율 |
|---|---|---|
| `congestion_rate` | 회귀 타깃 (%) | 평균 27.6 |
| `label_high` | 역×방향별 **train p95 초과** | **5.25%** |
| `label_extreme` | ≥ 100% | 0.61% |

### 라벨 정의를 바꾼 이유

기획서 v1 의 절대 임계(130% / 150%)는 실측 분포상 사용 불가였다.

| 임계 | 셀 수 | 비율 |
|---|---|---|
| ≥ 100% | 4,309 | 0.60% |
| ≥ 130% | 624 | 0.087% |
| ≥ 150% | **38** | **0.005%** |

150% 이상이 38셀뿐이라 Recall/Precision 이 통계적으로 무의미해진다. 역×방향별 p95 분위수 라벨로 전환했고, **임계는 train 구간에서만 산출해 valid/test 누수를 차단**했다.

## 6. 사전 등록한 통과 조건

학습 **전에** 정했고, 결과를 보고 바꾸지 않았다.

**판정: FAIL → baseline 채택.**

## 7. 성능

### 7-1. Baseline ladder (valid, 학습에 나온 역)

| 수준 | MAE | RMSE | R² | PR-AUC | Recall@P≥0.5 | 미관측 역 coverage |
|---|---|---|---|---|---|---|
| L0 전체평균 | 15.342 | 19.878 | 0.000 | 0.056 | 0.000 | 1.00 |
| L1 노선×방향×요일×시간대 | 11.115 | 15.401 | 0.400 | 0.134 | 0.000 | 1.00 |
| **L2 역×방향×요일×시간대** | **2.364** | **4.575** | **0.947** | **0.857** | **0.892** | **0.00** |
| L3 L2+최근스냅샷 | 2.763 | 5.327 | 0.928 | 0.847 | 0.912 | 0.00 |

**L1→L2 에서 MAE 가 11.1→2.4 로 급락한다.** 혼잡도를 결정하는 것은 압도적으로 "어느 역인가"다.
**L3 가 L2 보다 나쁘다.** 최신 스냅샷 하나보다 6개 평균이 안정적이며, recency 가 도움이 되지 않는다.

### 7-2. 모델 vs baseline

| Regime | 모델 | MAE | R² | Skill Score |
|---|---|---|---|---|
| A. 시간축 valid | L2 baseline | **2.364** | 0.947 | (기준) |
| A. 시간축 valid | LGBM Model-1 | 3.174 | 0.925 | **−0.464** |
| B. 미관측 역 valid | L1 baseline(폴백) | **11.019** | 0.401 | (기준) |
| B. 미관측 역 valid | LGBM Model-2 | 11.291 | 0.354 | **−0.012** |
| C. 시간축 test(2026) | L2 baseline | **2.215** | 0.962 | (기준) |
| C. 시간축 test(2026) | LGBM Model-1 | 2.947 | 0.949 | −0.330 |

```
Skill Score = 1 − MAE_model / MAE_reference     (양수면 개선)
```

Regime B 의 −0.012 는 사실상 동률이다. "모델이 졌다"가 아니라 **"노선 평균과 구별이 안 된다"**가 정확한 서술이다.

### 7-3. Ablation study

| 피처군 | 피처 수 | MAE | R² | PR-AUC |
|---|---|---|---|---|
| A. 시간만 | 9 | 11.235 | 0.391 | 0.136 |
| B. +역속성 | 14 | 10.518 | 0.450 | 0.146 |
| **C. +승하차flow** | 23 | **6.986** | **0.734** | **0.245** |
| D. +역식별자 | 24 | 3.460 | 0.916 | 0.718 |

**B→C 가 이 프로젝트가 48개월 승하차 데이터를 쓰는 이유다.** R² 0.450 → 0.734.
C→D 도 정직하게 본다. 역 식별자를 넣으면 R² 가 0.916 으로 또 뛴다. **모델이 역을 외우고 있다**는 뜻이고, baseline 이 이기는 이유이기도 하다.

### 7-4. 설명가능성 (SHAP, Model-2 기준)

폐기한 Model-1 이 아니라 **실제 운영에 쓰는 Model-2** 를 설명한다.

## 8. 주요 오류 케이스

### 8-1. 고혼잡 구간일수록 부정확하다 (가장 중요)

| 혼잡 구간 | 건수 | MAE |
|---|---|---|
| ~30% | 95,464 | 1.474 |
| 30-60% | 51,227 | 3.218 |
| 60-80% | 6,920 | 5.951 |
| 80-100% | 1,974 | 7.428 |
| 100-130% | 825 | 9.057 |
| **130%+** | 136 | **9.227** |

**"MAE 2.364" 는 저혼잡 구간에 희석된 평균값이다.** 정작 서비스에 중요한 고혼잡 영역에서는 6배 부정확하다. 이 사실을 밝히지 않고 2.364 만 제시하는 것은 오도다.

**서비스 함의**: 고혼잡 경고는 절대값보다 **상대 순위(p95 초과 여부)** 로 제공한다. 실제로 `label_high` 탐지 성능은 PR-AUC 0.857, Recall@P≥0.5 0.892 로 양호하다.

### 8-2. 노선별 편차

| 호선 | MAE | p95 오차 | 평가 |
|---|---|---|---|
| 8 | 3.600 | 13.867 | 가장 나쁨 |
| 2 | 2.943 | 10.377 | 나쁨 (순환선·지선 혼재) |
| 5 | 2.513 | 7.567 | 보통 |
| 3 | 1.615 | 5.333 | 좋음 |
| 7 | 1.760 | 5.600 | 좋음 |

8호선은 역 수가 19개로 적고 별내선 연장(남위례 2023-12 개통)으로 스냅샷 간 패턴이 변했을 가능성이 있다. **미확인 — 추가 조사 필요.**

### 8-3. 미관측 역에서 baseline 은 무력하다

L2 baseline 의 미관측 역 coverage 는 **0.00** 이다. 학습에 없던 역은 값 자체를 만들 수 없다. 신설역이 생기면 Model-2 로 보간해야 한다.

## 9. 알려진 편향

**`label_high` 기준의 불일치.** 라벨은 역×방향별 train p95 로 정의되는데, station holdout 의 56개 역은 train 에 없어 **전역 p95(약 54%)로 대체**된다. 즉 미관측 역의 라벨 기준이 다른 역과 다르다. Regime B 의 분류 지표(PR-AUC 등)는 이 편향 위에서 계산된 값이다.

지표를 추가해 해결되는 문제가 아니라 **한계로 기록해야 하는 문제**다.

## 11. 개선 방향

1. **혼잡도 산식 확인** → 체감시간 환산 파라미터(`κ`, `C0`)에 근거 부여
2. **8호선 오차 원인 분석** → 별내선 연장 전후로 스냅샷 분리 검토
3. **고혼잡 전용 모델** → 회귀 대신 `label_high` 직접 분류로 학습해 고혼잡 영역 성능 개선
4. **역 유사도 기반 보간** → 미관측 역에 노선 평균 대신 유사 역 가중 평균 적용
5. 스냅샷 누적 시 재학습 → 격자당 관측치가 20개를 넘으면 모델이 baseline 을 이길 여지 발생

## 11-1. 파생 사용처 — 경로 스코어링

이 모델의 출력은 경로 추천의 **체감시간 환산**에 쓰인다.

```
perceived_time = travel_time × (1 + 0.5 × max(0, 기대혼잡도 − 80) / 100)
edge_cost      = perceived_time + transfer_penalty + event_risk
```

v1 에서는 여기에 **환승 후 대기시간**(30분 평균 배차간격 / 2, 상한 12분)이 더해진다.
최초 승차 전 대기는 더하지 않는다.
