# Known Data Issues

여유로 서울은 공공데이터를 그대로 신뢰하지 않고, 역명·호선·방향·환승 방면·운행 구조를
교차검증한 뒤 사용한다. 이 문서는 v1 개발 과정에서 확인한 원본 데이터 이상값과
처리 방식을 기록한다.

각 항목은 **관찰한 사실**과 **우리가 내린 처리 판단**을 구분해 적는다.
원본 데이터를 임의로 고쳐 저장하지 않는 것이 이 프로젝트의 원칙이다.

## 1. 강동역 5→5 환승 방면 자기역명 이상값

**Status**: v1 UI hotfix applied
**Impact**: 환승 호차/문 안내는 유지, 잘못된 방면 문구만 숨김
**원본**: `서울교통공사_수도권 도시철도 환승 데이터.csv`

### 관찰

강동역 5호선 → 5호선 환승은 원본에 두 행뿐이며, 두 행 모두 `하차 열차 방면` 이
환승역 자기 자신인 `강동 방면` 으로 기재돼 있다.

```
환승시작역  하차 열차 방면   하차위치   환승 열차 방면   승차위치   소요시간
강동        강동 방면       1-1        둔촌동 방면      1-1       02:35
강동        강동 방면       1-1        길동 방면        1-1       02:35
```

"강동역에서 강동 방면으로 하차" 는 성립하지 않는다. 다른 환승역은
`잠실 8→2 : 몽촌토성 방면 / 석촌 방면` 처럼 실제 인접역이 들어가 있다.

강동은 5호선 본선(천호↔길동)과 마천지선(둔촌동)이 갈라지는 분기역이다.
둔촌동에서 온 열차는 강동을 지나 천호 방면으로 계속 가므로,
`천호 방면` 이 실제에 부합하는 표기다.

### 부작용

`transfer_tip()` 은 경로의 직전 역으로 "직전 역이 아닌 쪽" 을 골라 방면을 좁힌다.
두 행의 `arrive_toward` 가 동일하므로 이 필터가 아무것도 걸러내지 못한다.
결과적으로 `depart_toward`(둔촌동/길동) 만으로 행이 선택된다.
이번 케이스는 두 행의 하차 위치가 1-1 로 같아 호차/문 안내 자체는 정확하다.

### 처리

원본을 수정하지 않고 **표시 단계에서만** 방어한다.

- `station_routing.is_valid_toward()` — 방면 표기가 환승역 자기 자신을 가리키면 무효
- `station_routing.transfer_basis_text()` — 무효한 방면 문구만 생략, 나머지는 그대로

판단은 substring 이 아니라 **정규화 후 완전 일치**로 한다.
`'방면'` 을 제거하고 공백을 없앤 뒤, **끝의 `'역'` 만** 떼어 비교한다.

```
'강동 방면'              -> '강동'
'서울역'                 -> '서울'
'동대문역사문화공원 방면' -> '동대문역사문화공원'   (중간의 '역' 은 보존)
```

단순 포함 검사로는 302행 중 18행이 걸리지만, 이 중 16행은 오탐이다.

| 오탐 사례 | 실제 |
|---|---|
| 동대문 ⊂ 동대문역사문화공원 | 서로 다른 역 |
| 잠실 ⊂ 잠실나루 / 잠실새내 | 서로 다른 역 |
| 왕십리 ⊂ 상왕십리 | 서로 다른 역 |

정규화 완전 일치 기준으로는 **강동 2행만** 무효로 판정된다.

### 화면

```
변경 전 : 강동 방면 하차 · 길동 방면 승차 기준
변경 후 : 길동 방면 승차 기준
양쪽 무효 시 : 환승 위치 기준
```

호차/문 안내(`하차 위치` / `승차 위치`)는 그대로 표시한다.
무효한 방면 때문에 `transfer_tip` 전체를 버리지 않는다.

### 검증

`tests/test_transfer_direction.py` (27건)

- 정규화 규칙
- 자기역명 무효 판정
- substring 오탐 방지 (잠실/잠실나루, 왕십리/상왕십리, 동대문/동대문역사문화공원)
- 기준 문구 생성 (한쪽 무효 / 양쪽 무효 / 양쪽 정상)
- **마트 실측 검사** — 무효 방면이 강동 2행 외에 새로 생기면 실패한다

### 남은 과제

경로의 앞뒤 역으로부터 방면을 유도해 `천호 방면` 을 표시하는 방식은
**v1.1 개선 과제**로 남긴다. 원본에 없는 값을 만들어내는 것이므로,
"환승 호차/문은 원본에 있는 조합만 표시한다(추정 금지)" 원칙과의 관계를
먼저 정리해야 한다.

## 2. 5호선 둔촌동·올림픽공원 호선 오기입 156행

**Status**: v1 preprocessing correction applied
**Impact**: 혼잡도 mart 생성 전 호선 정정
**원본**: `서울교통공사_지하철혼잡도정보` 2024-06-30 스냅샷

### 관찰

5호선 둔촌동·올림픽공원이 `호선` 컬럼에 **2호선**으로 기재돼 있다.
두 역은 2호선에 존재하지 않는다.

교정하지 않으면 두 역의 혼잡도가 2호선 구간에 붙어 경로 그래프의
승차 엣지와 혼잡도 매칭이 어긋난다.

### 처리

`scripts/03_build_stg_congestion.py` (266~273행)

역번호 체계가 노선별로 배타적이라는 성질을 이용해, **역번호로 호선을 역산**하고
원본 `호선` 값과 대조한다. 역명 하드코딩이 아니라 코드 체계 기반이므로
같은 유형의 오기입이 다른 역에서 발생해도 함께 잡힌다.

```python
out["line_id_raw"] = out["line_id"]
out["line_id"] = [self._line_from_code(c, l)
                  for c, l in zip(out["station_code"], out["line_id"])]
out["is_line_corrected"] = (out["line_id"] != out["line_id_raw"]).astype(int)
```

원본 값은 `line_id_raw` 로, 교정 여부는 `is_line_corrected` 플래그로 보존한다.
덮어쓰지 않으므로 사후에 무엇이 몇 건 바뀌었는지 추적할 수 있다.

### 규모

**156행**. `reports/data_quality/` 의 stg 리포트에 건수가 기록된다.

## 3. 9호선 개화역 상선 0값

**Status**: out of v1 scope, v2 validation required
**Impact**: v1 앱 결과에 영향 없음
**원본**: `20XX년 9호선 역별 시간별 혼잡도 자료.xlsx` (2020~2025, 6개 연도)

여유로 서울 v1 의 범위는 서울교통공사 관할 1~8호선이며 **9호선은 포함하지 않는다.**
아래는 v2 확장을 검토하며 확인한 관찰 사실이고, 오류로 확정한 것이 아니다.

### 관찰

`상선일반(평일)` 시트에서 개화역이 **2020~2022년에는 전 시간대 0**이고,
**2023년부터는 값이 존재**한다(2025년 상선평일 시간대 합 143.8).

9호선 상선은 개화 → 중앙보훈병원 방향이므로 개화는 상선의 기점이다.
같은 시트에서 상선 종점인 중앙보훈병원은 전 연도 0이고,
하선 시트에서는 기점인 개화가 전 연도 0이다.

즉 **진행 방향의 종점이 0인 것은 일관되지만, 기점인 개화의 상선 값이
연도에 따라 0과 실측값으로 갈린다.**

### 가능한 해석 (미확정)

- 2020~2022년에 해당 격자를 측정하지 않았고 결측을 0으로 채웠다
- 혼잡도 산정 기준점(출발역 기준 재차율 등)이 연도별로 바뀌었다
- 기점 구간의 정의가 변경되었다

어느 쪽인지 원본 정의 없이는 판단할 수 없다.

### v2 확장 시 재확인 사항

1. 혼잡도 산식의 기준 — 정원 대비 %인지, 어느 구간을 기준으로 하는지
2. 상선/하선 방향 체계 — 서울교통공사 1~8호선 데이터의 `상하구분` 과 정합하는지
   (9호선은 행 순서가 두 시트 모두 개화부터라, 하선은 진행 방향과 행 순서가 반대)
3. 기점·종점의 혼잡도 산정 방식
4. **결측을 0으로 채웠는지 여부** — 0을 실측값으로 오인하면 기대 혼잡도가 낮게 추정된다
5. 연도별 스키마 차이 — 2022년 이후 평일 시트에만 00:00~00:59 두 구간이 추가된다
   (평일 39개 / 휴일 37개 시간 구간)

9호선은 서울교통공사 관할이 아니어서 승하차 인원, 역간거리·소요시간, 열차운행현황,
환승 호차/문 데이터가 현재 프로젝트에 없다. 혼잡도만으로는 경로 그래프에
올릴 수 없으므로, 확장 여부는 위 재검증과 함께 별도로 판단한다.
